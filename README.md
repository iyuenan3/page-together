# pageTogether

给自己和朋友的共享文档与画板空间。

Invite-only documents and whiteboards for friends, built with BlockSuite and Yjs. In development.

pageTogether 希望让受邀成员在浏览器里共同记录、整理和创作。文档与画板共享同一套内容，进入空间无需邮箱注册。

## 产品方向

以下为已确认的产品目标，尚未全部实现：

- 通过邀请进入同一个共享空间，填写昵称参与，无需邮箱注册。
- 在原生正文与画板之间切换，共同编辑空间内的文档。
- 完整保留选定 BlockSuite 版本的原生编辑能力，并逐项验收。
- 采用空间级管理、编辑、查看三档权限；整篇文档仅管理者可删除和恢复，服务端负责鉴权、撤权、附件与资源限制。
- 支持已缓存文档的离线编辑，正常重连自动合并，异常时保留离线稿；实现持久化和可验证的备份恢复，所有者使用离线恢复码恢复访问。

初期按最多 10 人同时在线、单个附件 50 MB 设计与验证。具体需求和验收标准见 [PRD](AIREADME/PRD.md)。

## 附件与离线缓存

打开文档后使用“添加附件”，或沿用原生编辑器的附件入口。文件先保存到此设备，再按当前身份和文档状态上传；引用新附件的正文会等待附件保存确认。已缓存原文件可在“附件与离线缓存”中断网下载，未缓存文件需要联网。

该窗口提供缓存文件预览：图片、浏览器支持的音视频、PDF 和 UTF-8 文本。PDF 使用随应用打包的 PDF.js，可分页显示中文、横向及扫描页面；正文内嵌共用该阅读器，已缓存后可断线刷新读取。加密、损坏或渲染超时的 PDF 提示下载原文件。阅读器及字体、解码资源来自本机应用，不向外部转换服务发送附件。文本最多预览前 128 KiB，HTML 等内容按纯文本显示；音视频编码仍依赖浏览器支持。Office 文档、压缩包、未知格式提供原文件下载。缓存预览只读，不修改正文。实际验证范围见能力记录。

网络和空间配额异常时保留原文件供重试。会话失效、权限变化或文档状态变化后，异常附件保持暂停；先恢复身份、处理旧正文并打开当前获准编辑的文档，再选择“确认重新提交到当前文档”。该操作追加新的附件卡片，同时保留原文件副本。备份恢复前的附件也可按此方式处理，旧正文不会随附件重新提交自动写回。

本机保存失败时保留页面，可下载内存原文件并重试本机保存。若文件尚未成功添加到正文，落盘后会提示明确重新提交。首版不自动清理离线附件及原始副本。

## 多文档与导入导出

原生文档引用可导航到同一空间中的文档，支持原生行内、卡片和同步嵌入。带定位参数的引用可打开目标正文段落、数据库行详情或画板画框及坐标区域，刷新与前进后退保留定位；目标已删除时明确提示。导出的同源文档链接可直接打开，访问仍需有效成员身份。数据表继续使用原生表格和看板，支持嵌套筛选及原生数字格式。创建时间来自记录元数据，只读显示；没有历史元数据的旧记录不推测创建时间。

“导入导出”提供以下入口：

- Markdown、HTML、文本用于内容交换，复杂块、交互和附件可能无法完整保留；数据表可能投影为静态表格或文字。独立待办汇总请使用原生 ZIP，文本格式不保留其跨文档汇总和交互。含图片的 Markdown/HTML 会连同资源导出 ZIP。
- 当前文档或空间原生 ZIP 用于迁移内容，保留原生块、数据视图、画板和附件。导入创建新文档并重映射包内引用；包外引用仍指向原文档，不覆盖已有内容。
- 可导入 Markdown、HTML、文本、兼容的原生 JSON 或 ZIP。Notion HTML 包需勾选“按 Notion HTML 解析”；已验证合成的嵌套页面、图片与包内链接，未覆盖所有 Notion 导出类型。
- PNG/PDF 使用原生视觉导出，画板中的中文和图形已在 Chrome 实际下载验证。PDF 是视觉结果，不是可编辑的原生内容备份；内置浏览器的下载交付仍有兼容边界。修改页面样式的浏览器扩展也可能影响文字导出，建议在无扩展窗口导出并检查文件。

复杂内容优先使用原生 ZIP。实测 Markdown/HTML 会丢失部分颜色、列表编号和代码显示选项，Markdown 下划线可能变为字面标签，HTML 不保留本轮公式、提示块与 PDF 附件。数据表仅导出静态值和带时区的创建时间，筛选与数字显示格式仍需原生包保留。

导入需要联网和编辑权限。每批最多 100 篇文档、2000 个文件，压缩包及解压内容各不超过 100 MB，单文件 50 MB、单篇文本或原生 JSON 10 MB；服务端正文及空间限额仍独立生效。这些是保护上限，当前原生往返实际覆盖 25 篇文档，并非 100 篇容量承诺。导入前校验格式、块版本与附件；中途失败时保留已创建内容供检查，不自动清除。原生 ZIP 仅迁移内容，身份、权限与完整服务恢复使用下述 `server:admin` 备份。

在正文输入 `/` 后选择原生 `Todo`，可插入独立待办汇总。完成状态写回来源文档，来源链接打开原始待办；标题在原文编辑，分类等自定义属性保存在当前汇总中。来源删除后退出汇总，恢复后按新代际重新读取。离线汇总仅包含本机已缓存且仍可读取的来源，读取不完整时会提示。

表格左侧把手可拖动来自不同文档的待办，顺序保存在当前视图，支持撤销重做，不移动来源正文中的块。字段排序优先于手动顺序；看板继续使用原生分类和分组内顺序。来源暂时缺失时保留其已存顺序，新发现的待办追加到末尾。服务不可达时只显示本机已缓存且仍可读取的来源，并提示尚未完成联网核验。

来源创建时间取自原始待办的历史元数据，只读显示。复制属性时保留零值、勾选值和富文本，文字副本可以独立编辑。原生隐藏图片类型可读取已有图片值、隐藏列及作为桌面看板封面；空值显示为空白，失效地址按浏览器失败状态显示。该类型没有新增上传或替换编辑器，外部图片的离线可用性取决于资源本身；本轮验证的是原生内容内嵌的合成 PNG。

画板沿用 Inter、Kalam、Satoshi、Poppins、Lora、BebasNeue 和 OrelegaOne。首次使用需联网加载上游字体资源，成功加载后可在本机缓存供离线使用；加载失败会提示可能显示备用字体，形状和字体选择仍保留。

## 本地开发

使用 Node.js 22，版本至少为 22.13.0。在仓库根目录运行：

```sh
npm ci --ignore-scripts
npm rebuild better-sqlite3
npm run build
PAGETOGETHER_DATA_DIR=.local/dev-data npm run server:admin -- init '本机测试所有者'
PAGETOGETHER_DATA_DIR=.local/dev-data PAGETOGETHER_ORIGIN=http://127.0.0.1:3000 npm run server
```

打开 `http://127.0.0.1:3000`，使用初始化输出的恢复码进入，并离线保存轮换后的新码。初始化只对新数据目录执行一次；恢复材料不写入仓库或日志。数据和验证产物在忽略目录中，服务仅监听回环地址，按 `Ctrl+C` 停止。这是临时开发验证方式，尚无已部署的服务。

使用热更新时，另启 `npm run dev`，把后台的 `PAGETOGETHER_ORIGIN` 设为 `http://127.0.0.1:5173`；Vite 将 `/api` 代理到本机后台。`/lab.html` 保留独立内存验证页，刷新会重置。离线重开需使用已缓存的构建产物。

| 命令 | 用途 |
|---|---|
| `npm run check` | 检查宿主代码与上游发布声明的类型兼容性 |
| `npm run build` | 类型检查、前后端构建、离线资源缓存与第三方许可清单 |
| `npm test` | 保存确认、权限、备份恢复、离线暂停、附件、原生创建、目录竞态及迁移边界回归 |
| `npm run test:capacity` | 新建隔离数据，验证 10 人、40 条文档连接、50 MB 附件与备份恢复；方案和边界见 CAPACITY |
| `npm run dev` | 本机热更新开发，需另启后台 |
| `npm run server` | 运行构建后的完整服务，必须配置 Origin |
| `npm run server:admin -- backup .local/new-backup` | 备份到尚不存在的目录 |
| `PAGETOGETHER_DATA_DIR=.local/restored npm run server:admin -- restore .local/new-backup` | 恢复到全新目录，默认暂停访问并轮换凭据 |

当前基线固定为 BlockSuite 0.22.4、Yjs 13.6.33，宿主使用 TypeScript、Lit 与 Vite。后台为 Node.js 22、better-sqlite3 13.0.3 和 ws 8.22.0，首版单实例、本机可靠磁盘保存；数据库提交不等于异机备份完成。`TestWorkspace` 仅用于验证页，技术边界和当前限制见 [ARCHITECTURE](AIREADME/ARCHITECTURE.md)，实际接口和保护限额见 [SPEC](AIREADME/SPEC.md)。
