# MEMORY

尚无本项目运行事故。后续只追加已实际发生并有证据的现象、根因、结论与预防，不将预期风险冒充已踩坑。

## 2026-10-09 · 发布源码包的开发模式接入

现象：生产构建预览能渲染，但开发页面空白。先出现装饰器 SyntaxError，随后出现 vanilla-extract file scope 错误和 CommonJS 导出缺失。

根因：BlockSuite 0.22.4 包直接导出 TypeScript 源码。vite-plugin-wasm 3.6.0 在 configResolved 将依赖预构建目标设为 esnext，普通 target 设置会被覆盖。预构建原生包还绕过 Vite 的 .css.ts 处理；排除源码包后，其外部运行依赖和深层导入需要明确预构建。

结论：显式设置 optimizer 的 supported.decorators=false；将导出源码的 BlockSuite 包排除，仍交由 Vite 样式插件处理；用 TypeScript AST 收集实际 import、export 和动态 import，跳过纯类型与 JSON 资产，将外部运行入口交给 optimizer。已在真实开发浏览器回读正文渲染。

预防：同时验证 npm run dev 和 npm run build 后的预览；构建成功不能代替开发页面实际加载。生成类型配置内容未变化时不改写，避免触发开发服务器无效重载。

## 2026-10-10 · 无缓存文档的首次同步与原生挂载

现象：回收站恢复生成新文档代际后，标题出现但正文空白，浏览器报告 missing root block；已有缓存的刷新路径正常。

根因：本机读取完成就结束 prepare，没有等待无缓存文档的首轮服务端同步，原生 Store 在根块到达前挂载。晚到的 Yjs 数据不能修复已失败的组件生命周期。

结论：已有缓存时先加载本机内容，无缓存的既有文档先等待首轮同步，再创建编辑器上下文；新建文档由明确的初始化路径处理。网络错误允许重新打开，真实空文档不直接挂载。已复验首次受邀的新成员和删除恢复后的新代际，正文完整渲染。

预防：同时测试有缓存、首次访问、新建和恢复后的代际，不能用同一成员的浏览器缓存替代首次加载验收。连接恢复后清除对应旧网络提示，成员切换时阻止原成员离线稿自动上传。

## 2026-10-11 · 实时降权后的离线角色缓存

现象：在线从编辑降为查看后，原生编辑器只读且服务器拒绝写入，但断网刷新又出现编辑入口，能产生仅本机保存的修改。

根因：重连时只更新内存成员和原生 Store，没有把已核实的新角色写入本机身份元数据；离线启动沿用首次进入时的编辑角色。

结论：当前成员核验后同时通知宿主更新本机身份元数据，不改动离线稿或认证 Cookie。已在真实 Chrome 用新构建复验页面内降权、断网刷新和粘贴尝试，离线重开保持只读；权限变化期间的异常修改未进入服务器。

预防：角色变更需同时检查在线页面、离线重开、本机缓存和服务端结果。浏览器网络面板切换 Offline 不一定断开已有 WebSocket，需离线刷新并确认请求出现 ERR_INTERNET_DISCONNECTED，再断言断线期间的修改互不传播。

## 2026-10-12 · 成员操作后的弹窗状态未刷新

现象：管理者移除成员后，服务端已停用该成员，Chrome 既有连接也停止同步，但管理弹窗仍显示原名称和“移除”按钮。

根因：成员行的操作只提交 PATCH，未使用返回的成员数据更新行对象与控件；后续操作还会读取弹窗首次打开时的角色和资格。

结论：提交成功后使用服务端返回值更新成员行、角色和资格按钮，提交期间禁用相关控件。已用真实界面连续保存新角色、恢复资格和再次移除，并核对数据库中的角色与停用状态；恢复资格没有使旧 Chrome 会话重新有效。

预防：权限操作同时检查服务端执行结果和当前弹窗显示，并连续执行下一项操作，不能只关闭重开弹窗后验证。


## 2026-10-12 · 恢复身份使异常离线稿重新上传

现象：Chrome 离线期间编辑，服务端会话过期或成员被移除后，首次重连显示暂停，管理者未收到修改；恢复原成员身份并重新登录后，这些旧稿却自动进入管理者文档并显示云端保存。

根因：blocked 只在 DocumentSync 内存中，重新创建同步器会沿用同一作用域的 IndexedDB 待发记录。仅核验当前角色无法识别已发生的撤权或降权历史。

结论：持久保存暂停原因和授权版本，恢复身份不清除异常暂停。明确重新读取云端时先保留完整旧稿，再隔离待发队列。修复后独立 Chrome 与内置 Chromium 重验过期及离线撤权，重新授权和登录均未自动回写；真实下载的导出文件包含对应异常稿且没有读取错误。

预防：异常场景需持续测试到刷新、恢复资格、恢复身份及随后重新打开，不能在首次提示暂停时结束。旧备份测试须先确认备份中确有有效会话、未兑换邀请和活跃成员，再在备份后撤权并恢复，防止因原凭据本已过期而误判保护有效。

## 2026-10-12 · 本机保存失败状态被后续编辑覆盖

现象：实际 IndexedDB 写入失败后，再次编辑可能把失败提示替换为正在同步或本机已保存，未落盘的完整稿仍只存在于内存。

根因：DocumentSync 虽阻止发送，但状态更新没有保留失败；重试若仅清除失败标志，已经丢失的增量也不能靠后续增量补回。

结论：失败持续到明确重试成功，重试保存完整内存快照；异常暂停与存储失败分别处理。自动化实际中止 IndexedDB 事务并核对未上传、完整导出、重开和重试，另覆盖服务器已收而本机确认清理失败。Chrome 将站点配额降到低于现有占用后，真实写入失败、继续编辑、实际导出及恢复配额后的明确重试均通过。

预防：故障测试必须确认实际存储机制被触发，并检查后续编辑和确认清理路径。删除状态保护的编译产物变异会使故障回归失败，恢复后通过；不能仅把界面状态手工设为失败来证明保护。

## 2026-10-12 · IndexedDB 请求失败先于事务完成拒绝

现象：实际中止事务的测试同时出现未处理 Promise 拒绝，即使调用方已经捕获存储方法的错误。

根因：请求先拒绝使方法提前退出，尚未 await 的 tx.done 随后拒绝且无人观察。

结论：创建显式事务时立即观察 tx.done 的拒绝，仍按顺序等待请求与事务提交并向调用方报告失败。实际事务中止回归不再产生未处理拒绝，不吞掉存储失败。

预防：同时测试请求 Promise 与事务完成 Promise 的失败时序，不以正常提交测试替代。

## 2026-10-12 · 附件排队与离线所属文档记录

现象：排查附件队列时发现，上传期间加入的新文件可能错过当前遍历；若新附件只在会话核验成功后绑定文档，断网重开会失去内存中的待绑定标记，普通离线文件也被当作无法核验的旧附件。

根因：发送中的 flush 直接返回已有 Promise，没有安排下一轮；所属文档绑定位于联网核验之后，离线时无法持久化来源。

结论：发送期间的新入队触发继续排空；新附件在尝试联网前，先依据实际原生块引用持久绑定所属文档。自动化覆盖上传中入队、离线来源落盘和持久层重开，真实 Chrome 断网新增、再次刷新及重连自动上传通过。删除这两项编译产物保护会使相应回归失败，逐字恢复后通过。

预防：附件验证需跨越上传期间入队和离线页面重开，不能只验证单个在线文件。旧回执按队列记录 ID 确认，不能确认后来重新提交的记录。

## 2026-10-12 · 附件本机保存失败后原文件与旧提示

现象：Chrome 实际存储配额不足时，附件正文卡片没有创建，文件仍需保留；补齐内存原件后，明确重试落盘成功，界面却继续显示原先的保存失败提示，并提供没有正文引用可处理的普通上传重试。

根因：原生文件入口会在 BlobSource.set 失败时退出，不能依靠正文块保存原文件；重试只保存了数据，没有更新原生附件状态，也未区分已落盘但尚未添加到正文的文件。

结论：本机写入失败保留完整 File、文件名和类型，提供原件下载、明确本机重试及重新提交。重试成功清除旧错误；没有正文引用时提示确认重新提交并追加卡片。实际 2 MB 内存原件下载摘要一致，恢复配额后新构建的提示和重提回归通过；服务端保存确认的本机落盘失败另由实际事务中止覆盖。

预防：验证实际落盘机制失败、原始字节下载和恢复后的下一步操作，不能用失败提示本身替代数据保留证明。未取得附件保存确认的正文引用保留在本机。

## 2026-10-12 · 原生混合文件 drop 被首个处理器截断

现象：浏览器将真实 JPEG 与 PDF File 一起送入原生 drop 路径时，只出现 PDF；正文和画板都需要验证完整分组。

根因：BlockSuite 0.22.4 FileDropExtension 在第一个 onDrop 返回 true 后退出，两类处理器各自只负责部分文件；原生画板图片分支还将未过滤的全部文件传给图片创建入口。

结论：以该版本原生配置为基础，分别过滤图片和其他文件并继续混合链路，复用原生回调，查看 Store 直接拒绝。正文与空画板均收到两类块，JPEG 实际解码，独立成员读回通过；查看角色同样处理后块数与服务端修订号均未变化。自动化覆盖两种处理顺序，移除继续处理保护会使回归失败。

预防：不要只验证单个图片或单个附件。适配依赖上游私有 DI 标识，升级时复核。系统拖动自动化本轮未能将操作系统文件列表送入页面，原因尚不能确定；改用文件选择器取得真实 File 后发送浏览器 DragEvent，只证明实际编辑器处理、保存和授权路径，系统文件实际拖入仍待人工补验。

## 2026-10-12 · 无元数据图片预览与 UTF-8 故障测试

现象：另一成员缓存的原生图片缺少文件名和 MIME，直接按元数据分类无法预览。另在预览回归变异中发现，移除严格 UTF-8 解码后，原无效字节用例仍因包含 NUL 被另一道保护拒绝，未真正验证解码保护。

根因：原生图片块不保证携带附件卡片的元数据；故障用例同时触发两个保护，遮蔽目标保护缺失。

结论：无明确 MIME 时读取前 16 字节识别已知 PNG、JPEG、GIF、WebP 文件头，明确文档类型仍优先且按纯文本处理。远端无名 PNG/JPEG 实际解码通过。无效 UTF-8 用例改为不含 NUL，NUL 单独保留测试；继续处理混合链、文档 MIME 优先和严格 UTF-8 三项变异均先基线通过、移除保护后失败、逐字恢复后通过。

预防：故障测试分别击中各自机制，不能用共享错误提示证明每道保护有效。记录不确定的工具表现，避免把自动化文件事件当作操作系统拖动成功。

## 2026-10-12 · PDF 能力标志与实际页面不一致

现象：内置 Chromium 的 PDF 阅读器标志为真，原生附件和缓存窗口的 Blob iframe 仍未显示页面；Chrome 插件可显示同一原件。

根因：原实现把浏览器插件当作渲染依赖。能力标志只表示配置，不能证明该嵌入环境实际执行并显示 PDF。

结论：缓存与原生内嵌共用本地 PDF.js，实际核对中文、多页、横向及扫描页面、分页文字、加密和损坏提示。服务停止并刷新后，缓存阅读器、worker 和中文资源仍能绘制第二页。原件下载哈希相符，具体证据见能力记录。

预防：必须检查画布或实际页面内容，不能以 iframe、菜单或能力标志验收。模块 worker 的 .mjs MIME 与 nosniff 一起测试，字体及解码资源随应用缓存；新 MIME 缺陷注入被回归检出。

## 2026-10-12 · 富文本格式片段之间的空格丢失

现象：macOS 原生剪贴板粘贴含粗体、斜体和链接的 HTML 后，格式保留，但片段之间的普通空格消失；独立成员和 SQL 文档均读到连在一起的文字。

根因：0.22.4 的 HTML text matcher 把所有纯空白文本节点当作排版噪声丢弃，其中包括相邻行内元素之间有意义的空格。

结论：在公开文本匹配器扩展点补充纯空白节点折叠，保留代码、显式 trim 和其他原生解析。相同原生粘贴后空格、格式、链接、段落和列表均保留；图文组合撤销重做、原生多块跨文档及跨模式复制通过，服务端块类型、文字 delta 与附件键核对一致。

预防：剪贴板验证同时核对字符、格式和结构，不能只看文字存在。新空白回归通过基线、移除保护、失败、逐字恢复及通过的流程。

## 2026-10-12 · 同步 RxJS 订阅误捕获信号依赖

现象：加载图片和附件后，控制台反复出现 Cycle detected，堆栈指向上游 ResourceController.updateState。

根因：ResourceController 在 signal effect 内订阅 BehaviorSubject，首次状态同步送达；消费者合并状态时读取并写入同一信号，该读取被外层 effect 捕获，导致重新订阅与重复写入。

结论：生产 BlobEngine 仅在对原生消费者的状态通知周围使用 untracked，保留真实状态、同步时序及退订。重开已含图片和 PDF 的文档后未再出现循环日志。机制回归覆盖初次送达、后续状态、来源变化和退订；移除 untracked 会被回归检出。

预防：集成同步 Observable 与 signal effect 时核对依赖捕获边界。不能通过屏蔽错误、复制资源控制器或将状态推迟到任意定时器处理。

## 2026-10-12 · 画板 Note 遮罩拦截 PDF 阅读控件

现象：正文和缓存窗口的 PDF 分页可用，但 PDF 位于画板 Note 中时，点击下一页只触发原生选择，页码不变；查看成员同样无法翻页。

根因：BlockSuite 0.22.4 的原生 Note 遮罩处于内容之上并接收指针事件，阅读器按钮未建立局部层级，点击先被画板的选择行为处理。

结论：将 PDF 阅读器标记为不可编辑，仅提升分页和文字展开控件的局部层级，并阻止相关鼠标事件向编辑器冒泡，其余 Note 选择行为保留。独立 Chrome 查看成员的正文及画板分页、中文横向页、扫描页、末页禁用与返回上一页通过；系统文件和富文本写入尝试被拒绝，隔离对照的服务端修订号未变。最新构建和 54 项回归通过。

预防：嵌入控件需分别验证正文、画板和只读角色，不能用同一阅读器在缓存窗口可操作替代画板验收。原生 Note 自动布局可能由另一个编辑身份触发，权限验证应隔离其他编辑页面并比较服务端修订。


## 2026-10-12 · 原生立即初始化先于创建授权

现象：通过原生引用菜单创建文档后，新文档自己的正文被标记为无授权旧稿并暂停。

根因：createDefaultDoc 同步写入 Yjs，HTTP 目录创建和本机作用域授权记录仍在异步进行。保护原本针对未知旧队列，却误伤刚创建的合法初始化。

结论：只对带明确创建 Promise 的新作用域串行等待创建成功与授权确认，再保存原生初始化。创建失败仍保留本机内容并持久暂停，不普遍放行无授权队列。实际原生菜单创建及服务器保存通过；真实 Yjs 与 IndexedDB 回归覆盖成功、失败和旧暂停，移除准入等待会使回归失败，逐字恢复后通过。

预防：同时验证原生同步接口与异步宿主边界，不能仅从宿主等待完成后才写入的路径推断原生创建有效。

## 2026-10-12 · 批量目录广播与引用恢复缓存

现象：25 篇原生批量导入在中途停止，产生 13 个未初始化文档；另一场景中，已恢复目标的原生引用仍显示 Deleted doc。

根因：每篇创建引起多条连接广播，各自并发读取目录；较早的缺项结果晚到后退役了刚创建的 Doc。引用视图又缓存了缺失目标和旧 Store，不随目录代际恢复重新绑定。

结论：合并目录请求并串行处理，创建前后使跨越本地变更的结果失效，待创建项免于缺项误退役，较旧代际不覆盖当前状态。目录身份变化重绑原生上下文，操作锁及结果归属工作区。导入逐篇创建初始化；原有失败合成文档保留，不清除历史。修复后同一 25 篇包全部保存，6 个附件摘要一致，卡片和同步嵌入恢复无需刷新。旧目录保护移除后对应回归失败，恢复后通过。

预防：用延迟可控的目录读取验证乱序，用真实多篇包验证完整保存；操作面板可能在处理中被重建，锁和结果不能仅存在旧 DOM 内。

## 2026-10-12 · 文本适配器的空单元格与资源路径

现象：含空进度单元格的数据表无法导出 Markdown、HTML 或文本；含图片 ZIP 的文内 URL 与文件路径不一致，重新导入后缺图。

根因：固定版本进度格式化器对 undefined 调用 toString；原生图片导出使用 assets/文件名，而路径映射同时保存导入临时 ID，后者不能作为导出文件名。

结论：仅在文本导出的临时快照移除无值单元格，保留 0、false、实时数据和原生快照。资源包使用原生 getAssetName 生成同一条路径。修复后表格文本和含图 Markdown/HTML 实际下载、重新导入、图片解码与服务端摘要通过。

预防：以实际导出文件再次导入检查资源，原生 ZIP 同时核对原始字段，不用文本投影结果推断完整数据保真。数据属性菜单曾被固定视口裁切，限制原生菜单高度后实际选择字段可用，仍需继续验收不同视口与更多属性。


## 2026-10-13 · 嵌套筛选闭包保留旧条件

现象：复杂筛选实际结果已变化，但深层条件仍显示旧阈值；随后添加或切换条件可能把刚修改的值覆盖回去。

根因：0.22.4 的子组 computed 捕获首次渲染的 filter 对象，未跟随父组当前条件。最大深度分支又直接添加默认首字段，缺少任意字段选择。

结论：构建时将子组信号绑定当前条件，新增条件沿用原生字段菜单且遵守深度限制。实际连续修改阈值、添加 Checkbox、切换 AND/OR 均保留兄弟条件，7 条真值记录只匹配预期项。回归执行原生表达式和新增菜单方法，未修复源码作为旧闭包对照。

预防：复杂组不能只验首次渲染和一次求值，要在同一弹层连续编辑并核对条件文字、结果和持久数据；转换片段不匹配须停止构建。

## 2026-10-13 · 数字格式编辑破坏未改变的值

现象：37.50% 进入编辑后直接确认变成 3750.00%，0 进入编辑呈空并被清除；金额显示两位小数后直接确认会丢失原始精度。

根因：原生编辑器解析格式化显示串，却没有区分未变输入和明确修改；百分号未换算回原始比例，零值使用真假判断。

结论：仅适配原生输入片段，未变显示串直接保留原值，明确百分比输入除以 100，零值使用非空判断。实际输入 12.50% 保存为 0.125，金额输入保存为 2345.678；另一条未变金额保留 1234.567，零值直接确认仍为 0。安装包实际方法与格式化器回归包含未修复源码对照。

预防：数字验收同时核对显示、进入编辑、不修改确认、明确修改、非法值和清空，服务端或原生导出须核对原始数值。

## 2026-10-13 · 原生导入被作者服务重写历史元数据

现象：加入生产 WriterInfo 后，导入记录的历史创建时间变成导入当天，原生包不再精确往返。

根因：BlockMetaService 将 Transformer 创建的块视为本地新建，覆盖快照中既有创建和修改身份及时刻。

结论：仅在目标 ProductionDoc 的快照导入期间让 WriterInfo 返回空，finally 恢复当前身份。重新实际导入后历史时间和身份保留；真实新建记录仍有当前作者与时间，重启后独立 Chrome 可读。3 篇文档的 60 个完整块按包内文档引用映射后完全一致。

预防：启用宿主服务后重验原生导入，不只比较正文、列和图形，也比较块元数据；导入隔离不能影响其他文档或后续编辑。

## 2026-10-13 · 静态表格表头与计算属性

现象：字段顺序调整后，Markdown/HTML 第一列的表头为状态，实际值却是标题；计算创建时间列为空。

根因：原生 processTable 固定先输出标题值，但表头直接沿用列顺序；创建时间从块元数据计算，不属于其静态属性映射。

结论：仅在导出快照中把标题表头移至首列，并把创建时间投影为带 +08:00 的富文本值。实际两种下载均核对表头与 7 行值，回导静态表格正确。回归运行安装包实际 processTable，旧输入作为错位和遗漏对照，实时文档及原生快照不变。

预防：文本转换除能下载外，还要核对列名和值的语义对应、计算字段和资源；数字显示格式及交互保真使用原生包验收。

## 2026-10-13 · 跨文档引用丢失原生定位参数

现象：点击远端画框引用只打开目标文档，仍停留正文模式；URL 没有画框参数，刷新和返回无法复现定位。

根因：宿主引用事件只传 pageId，同源链接解析也只返回文档 ID，原生滚动锚点没有收到 HighlightSelection。

结论：保留并校验定位参数，等待原生视图挂载后聚焦，历史导航使用同一解析且不重复入栈。旧构建作为实际负对照，新构建在相距约 12000 单位的黄、蓝双画框之间正确聚焦；Chrome 刷新、前进后退及正文段落定位通过，缺失目标提示后仍可读取文档。

预防：引用保存了参数不等于点击完成定位。分别核对 URL、模式、实际视口、历史导航和当前文档身份，防止异步旧导航覆盖新选择。
