# MEMORY

尚无本项目运行事故。后续只追加已实际发生并有证据的现象、根因、结论与预防，不将预期风险冒充已踩坑。

## 2026-10-09 · 发布源码包的开发模式接入

现象：生产构建预览能渲染，但开发页面空白。先出现装饰器 SyntaxError，随后出现 vanilla-extract file scope 错误和 CommonJS 导出缺失。

根因：BlockSuite 0.22.4 包直接导出 TypeScript 源码。vite-plugin-wasm 3.6.0 在 configResolved 将依赖预构建目标设为 esnext，普通 target 设置会被覆盖。预构建原生包还绕过 Vite 的 .css.ts 处理；排除源码包后，其外部运行依赖和深层导入需要明确预构建。

结论：显式设置 optimizer 的 supported.decorators=false；将导出源码的 BlockSuite 包排除，仍交由 Vite 样式插件处理；用 TypeScript AST 收集实际 import、export 和动态 import，跳过纯类型与 JSON 资产，将外部运行入口交给 optimizer。已在真实开发浏览器回读正文渲染。

预防：同时验证 npm run dev 和 npm run build 后的预览；构建成功不能代替开发页面实际加载。生成类型配置内容未变化时不改写，避免触发开发服务器无效重载。

## 2026-10-10 · 无缓存文档的首次同步与原生挂载

现象：回收站恢复生成新文档代际后，标题出现但正文空白，浏览器报告 missing root block；已有缓存的刷新路径正常。

根因：本机读取完成就结束 prepare，没有等待无缓存文档的首轮服务端同步，原生 Store 在根块到达前挂载。晚到的 Yjs 数据不能修复已失败的组件生命周期。

结论：已有缓存时先加载本机内容，无缓存的既有文档先等待首轮同步，再创建编辑器上下文；新建文档由明确的初始化路径处理。网络错误允许重新打开，真实空文档不直接挂载。已复验首次受邀的新成员和删除恢复后的新代际，正文完整渲染。

预防：同时测试有缓存、首次访问、新建和恢复后的代际，不能用同一成员的浏览器缓存替代首次加载验收。连接恢复后清除对应旧网络提示，成员切换时阻止原成员离线稿自动上传。

## 2026-10-11 · 实时降权后的离线角色缓存

现象：在线从编辑降为查看后，原生编辑器只读且服务器拒绝写入，但断网刷新又出现编辑入口，能产生仅本机保存的修改。

根因：重连时只更新内存成员和原生 Store，没有把已核实的新角色写入本机身份元数据；离线启动沿用首次进入时的编辑角色。

结论：当前成员核验后同时通知宿主更新本机身份元数据，不改动离线稿或认证 Cookie。已在真实 Chrome 用新构建复验页面内降权、断网刷新和粘贴尝试，离线重开保持只读；权限变化期间的异常修改未进入服务器。

预防：角色变更需同时检查在线页面、离线重开、本机缓存和服务端结果。浏览器网络面板切换 Offline 不一定断开已有 WebSocket，需离线刷新并确认请求出现 ERR_INTERNET_DISCONNECTED，再断言断线期间的修改互不传播。

## 2026-10-12 · 成员操作后的弹窗状态未刷新

现象：管理者移除成员后，服务端已停用该成员，Chrome 既有连接也停止同步，但管理弹窗仍显示原名称和“移除”按钮。

根因：成员行的操作只提交 PATCH，未使用返回的成员数据更新行对象与控件；后续操作还会读取弹窗首次打开时的角色和资格。

结论：提交成功后使用服务端返回值更新成员行、角色和资格按钮，提交期间禁用相关控件。已用真实界面连续保存新角色、恢复资格和再次移除，并核对数据库中的角色与停用状态；恢复资格没有使旧 Chrome 会话重新有效。

预防：权限操作同时检查服务端执行结果和当前弹窗显示，并连续执行下一项操作，不能只关闭重开弹窗后验证。


## 2026-10-12 · 恢复身份使异常离线稿重新上传

现象：Chrome 离线期间编辑，服务端会话过期或成员被移除后，首次重连显示暂停，管理者未收到修改；恢复原成员身份并重新登录后，这些旧稿却自动进入管理者文档并显示云端保存。

根因：blocked 只在 DocumentSync 内存中，重新创建同步器会沿用同一作用域的 IndexedDB 待发记录。仅核验当前角色无法识别已发生的撤权或降权历史。

结论：持久保存暂停原因和授权版本，恢复身份不清除异常暂停。明确重新读取云端时先保留完整旧稿，再隔离待发队列。修复后独立 Chrome 与内置 Chromium 重验过期及离线撤权，重新授权和登录均未自动回写；真实下载的导出文件包含对应异常稿且没有读取错误。

预防：异常场景需持续测试到刷新、恢复资格、恢复身份及随后重新打开，不能在首次提示暂停时结束。旧备份测试须先确认备份中确有有效会话、未兑换邀请和活跃成员，再在备份后撤权并恢复，防止因原凭据本已过期而误判保护有效。
